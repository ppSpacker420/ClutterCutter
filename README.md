# ClutterCutter

Automated local storage manager. Scans a cluttered folder, categorises the
files it finds, and moves them into per-category subfolders.

**Nothing is deleted. Nothing is overwritten. Nothing moves until you ask.**

Runs on Windows and Linux. Python 3.10+, standard library only, no
dependencies.

> [!IMPORTANT]
> **This project was built with AI assistance** — for the specification, the

> before using or reviewing it. In short: AI wrote the code *and* the tests,

## Quick start

### Linux / macOS — install

```
curl -fsSL https://raw.githubusercontent.com/ClutterCutter/ClutterCutter/main/install.sh | bash
```

Installs to `~/.local/bin` — no `sudo`, nothing outside your home directory is
touched. Then:

```
cluttercutter ~/Downloads          # preview, moves nothing
cluttercutter ~/Downloads --apply  # actually sort
cluttercutter-gui                  # the GUI
```

If your shell doesn't pick up `~/.local/bin`, the installer says so and prints
the one line to add to your `.bashrc`.

> The GUI needs Python's **tkinter**, which is a system package rather than
> something pip can install. If the GUI doesn't start, the installer tells you
> the exact command for your distribution (`apt install python3-tk`,
> `dnf install python3-tkinter`, `pacman -S tk`, `brew install python-tk`).
> **The CLI works without tkinter.**

### Linux / macOS — from a clone

No install step needed. Clone and run:

```
./cluttercutter.sh              # GUI
./cluttercutter-cli.sh ~/Downloads
```

### Windows

Double-click **`ClutterCutter.bat`** for the GUI (no console window appears),
or run `cc-cli.bat "C:\Users\me\Downloads"` for the CLI.

### Any platform

With Python 3.10+ installed:

```
pip install .            # installs both commands
cluttercutter ~/Downloads
cluttercutter-gui
```

Or run straight from the source folder:

```
python -m cluttercutter.gui       # GUI
python -m cluttercutter <folder>  # CLI
```

### Options

| Flag | Effect |
| --- | --- |
| *(none)* | Preview only. This is the default. |
| `--apply` | Actually move the files. Prompts for confirmation unless `--yes`. |
| `--yes` | Skip the confirmation prompt. |
| `--include-protected` | Also move files whose type could not be identified. |
| `--recursive` | Descend into subfolders. Off by default. |
| `--json` | Emit the plan as JSON. |

## Safety model

Five rules, each enforced in code and covered by a test.

1. **Dry-run is the default.** There is no way to move a file by forgetting a
   flag, because the flag that moves is the one you have to type.
2. **Only the folder you name is touched.** Destinations are verified to be
   descendants of the target folder before any move is planned. Recursion is
   off by default.
3. **Nothing is deleted.** No code path removes a user file.
4. **Nothing is overwritten.** A name collision produces `report (1).pdf`. The
   existing file is never touched.
5. **Ambiguous files are left alone.** An unrecognised extension goes to
   `Protected` and is not moved unless you pass `--include-protected`. The
   tool prefers to leave a file alone over guessing at it.

Hidden and system files — including Windows hidden attributes that a
dot-prefix check would miss, such as `desktop.ini` — are excluded from the
plan and listed separately so nothing is invisible to you.

Notable cases covered: dry-run purity, protected-file handling,
case-insensitive collision detection on a case-insensitive filesystem,

and Windows hidden-attribute detection.

## Architecture

```
scanner -> planner -> mover
 (reads)   (pure)    (writes, only with --apply)
```

`scanner` and `planner` never write to disk. That is what makes the preview
trustworthy: the preview you see is generated by the same code that executes,
so it cannot drift from what a real run would do.

Both the CLI and the GUI call the same three functions, so there is no
CLI-only behaviour to disagree with the GUI.
